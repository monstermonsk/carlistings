# Paste into the engineering team's orchestrator

Build Crankshaft's Listing Tuner and standardized dealer portal as a service integrated with the **existing** Crankshaft website, AI verifier, SignalWire call routing and Crankshaft automation runtime. Do not rebuild those systems. Start by reading [Technical Build Specification](../Technical-Build-Spec.md), [Connector Catalog and Dealer Portal Specification](../Connector-Catalog-and-Dealer-Portal-Spec.md), [Core Media and ML Engineering Specification](../Core-Media-and-ML-Engineering-Spec.md), [Listing Accuracy Standard](../Listing-Accuracy-Standard.md), and the proposed [API contract](./contracts/listing-api.openapi.yaml). Inspect Crankshaft's own existing repositories before coding; this public package does not include their source or credentials. Do not make per-dealer system inspection a prerequisite: one standard interface, vendor product presets, secure authorization, site automation where permitted and CSV fallback are product requirements.

## First assignment: lead/integration agent

Produce `integration-map.md` and an architecture decision record for **Crankshaft's existing code**. Identify language/framework, identity/tenant model, verifier/SignalWire events and routing configuration, automation scheduler/agent/session/checkpoint APIs, hosting, database, queue and storage. Define stable `staff_id`, `call_id`, transfer attempt and answered-agent records. Replace proposed contract names with actual mappings and publish one shared OpenAPI/event schema version plus connector capability manifest. Create synthetic fixtures for two cars, a vendor feed, a phone walkaround, call attempts/answer/fallback, a CRM lead, an appointment, a website listing form and CSV export. Do not allow parallel agents to invent incompatible schemas. Flag vendor/site access and mock it until enabled.

## Parallel assignments after contracts merge

1. **Inventory/facts agent:** stock lifecycle, standard DMS connector interface, vPIC identity cache, dealer attestation/conflict API, sold/price change logic. Return current source revision and fact provenance.
2. **Capture/frontend agent:** existing-auth mobile upload flow, stock selection, photo/video prompts, resumable direct upload, operator/dealer review screens. Preserve the existing public site and login experience.
3. **Photo agent:** immutable originals, image QA/view classification, reproducible real-photo edit recipes and gallery selection. Sharpen as useful; do not remove dents, change car color/parts/condition or use synthetic vehicle imagery.
4. **Video agent:** probe, transcript/scene map, candidate intervals, optional Jev ranker behind a flag, edit decision list, FFmpeg renders, complete clip review and retake path.
5. **Copy/QA agent:** structured dealer-sourced claim generation, direct conflict/price/disclosure validation and channel variants. No generic VIN option promoted to installed without dealer attestation.
6. **Publishing/connectors agent:** provider manifest registry; secure OAuth/token connection flow; route selection among API/feed, existing Crankshaft site automation and CSV; one authorized inventory/syndication write path; listing/call CSV and media export; idempotent upsert/remove, receipt, live readback and sold withdrawal. Keep marketplace adapters behind site-specific authorization.
7. **Verifier/outcomes agent:** a nonblocking event bridge from the existing verifier and SignalWire router; per-leg attempted/answered salesperson record, stock/lead attribution with confidence, CRM/DMS appointment and confirmed-sale ingest or outcome CSV, listing-day exposure facts. Do not copy raw audio into the ML warehouse by default.
8. **ML agent:** begin with rules and the untrained photo-ranker starter, train only on authorized labeled media, hold out whole dealers/vehicles/future time, and report against a simple baseline. Build an exposure-aware qualified-appointment model only after trusted joins and denominators exist. Keep recommendations advisory until a prospective dealer test shows improvement.
9. **Platform agent:** tenant isolation, vault/KMS secret references, object rights/retention, queues/dead letters, contract CI, monitoring, feature flags, rollback, runbooks and fixture-driven end-to-end tests.
10. **Dealer portal agent:** Crankshaft-owned dealership/location/staff directory, routing configuration against the existing router, Connections UI, Calls list/detail showing attempts and answered agent, role-scoped export and correction audit.
11. **Site automation agent:** adapt the existing automation runtime to destination jobs, with versioned website recipes, permitted dealer sessions, preflight validation, human checkpoints, submit evidence, live readback, edit/withdraw and UI-drift pause. A form fill or submit click never means the listing is live.

Use the master specification's **WP-00 to WP-15** as ticket IDs and dependencies. Each PR must name its ticket, contract version, fixture, acceptance evidence, rollback, vendor mocks and effect on the existing live call path. Merge a vertical slice (staff setup → call/agent ledger, and upload → draft → approval → authorized API/feed/site automation or CSV → live check → verifier event → dealer outcome) before adding more vendors or a larger model. A failed listing job must surface a specific operator task; it must never interrupt a live call. Do not claim a trained model or conversion lift from the 40 example listings.
